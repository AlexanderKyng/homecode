Maintain a structured task list for the current coding session.

Use when:
- Work requires 3+ distinct steps
- Tasks are non-trivial and benefit from planning
- User provides multiple requests
- New instructions arrive and should be tracked
- Progress/status visibility is useful

States:
- pending
- in_progress (exactly one active item)
- completed
- cancelled

Rules:
- Update status as work progresses
- Mark a task in_progress before starting it
- Mark completed only after work and verification finish
- Keep one active task while work remains
- If blocked, keep in_progress and add a follow-up task
- Preserve user commands exactly
- Break large tasks into clear, actionable steps
- Add newly discovered follow-ups when relevant

Skip for:
- Simple one-step edits
- Basic tool calls
- Purely informational/chat requests

When uncertain, use the task list.
