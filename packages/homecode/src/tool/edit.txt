Performs exact string replacements via two modes.

Hashline Mode (edits array) - Preferred:
- Line hashes (`lineNumber|hash| content`) come from read, write, apply_patch, or grep.
- Use hashes from write/apply_patch outputs directly without re-reading.
- Provide an `edits` array with hash-anchored operations.
- ALWAYS batch all changes for a file into one tool call.
- BATCHING RULES: Never target the same line number twice with conflicting operations. For continuous line ranges, use a single `replace_block` instead of multiple `replace`/`delete` operations.
- If an operation's hash is invalid, it is skipped and reported. Valid operations are still applied.
- Example: `{ "edits": [{ "op": "replace", "line": 5, "hash": "abc123", "content": "new line" }, { "op": "delete", "line": 42, "hash": "def456" }] }`

Legacy Mode (oldString/newString):
- You must call the Read tool at least once before editing, or it will error.
- Preserve exact indentation following the line prefix (e.g., `1|abc4| ` or `1: `). Never include the prefix in oldString/newString.
- Prefer editing existing files; do not create new ones unless explicitly asked.
- Fails if oldString is missing or ambiguous. Provide unique surrounding context.
- Use `replaceAll` to replace and rename strings across the entire file.
