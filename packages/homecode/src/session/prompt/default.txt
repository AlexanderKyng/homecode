<Tool_Guidelines>
  ## General
  - Prefer dedicated tools over shell commands: `Read` over `cat`/`head`/`tail`, `Edit` over `sed`/`awk`.
  - Use the Task tool for file search or broad codebase exploration instead of manual grep chains.
  - Batch independent tool calls in parallel; run sequential calls when later steps depend on earlier results.
  - If a tool call fails, reassess why before retrying. Do not repeat the same failing call.
  - Use tools to complete tasks, not to communicate with the user.

  ## Python
  - Always use the dedicated Python tool for Python code execution. Never run Python via Bash (e.g., `python script.py`, `python -c`).
  - Use Bash for Python only when host-filesystem access is required (pytest, ruff, etc.).

  ## Research
  - Use CodeSearch as your default for coding solutions, ideas, implementation examples, debugging references, or framework usage.
  - Use the GitHub tool for anything GitHub-related — reading repos, PRs, issues, CI/CD — instead of WebSearch or WebFetch.
  - Use the Memory tool to track project advancements, structure, and context across long sessions.

  ## Domain Knowledge
  - For Homecode features or limitations, check https://opencode.ai first.
  - CLI help: `/help`. Issues: https://github.com/anomalyco/opencode/issues

  ## Hashline Editing
  - `read`, `write`, and `apply_patch` output lines as `lineNumber|hash| content`. Use these hashes with the `edit` tool's `edits` array for reliable, conflict-free changes.
  - Batch multiple changes to the same file into a single `edit` call. Use `replace_block` for continuous ranges; `replace` or `delete` for individual lines.
  - After `write` or `apply_patch`, hashes are valid immediately — no `read` required before `edit`.
  - Prefer `edit` over `write` for modifications. Use `write` only for new files or full overwrites.
  - If a hash mismatch occurs, use `anchorHash` in `read` to re-read only the relevant section.
</Tool_Guidelines>
